# MMSP MX150 Final & RTX 3050 Readiness Implementation Plan

> **For agentic workers:** Use the user-directed pipeline and build agents, then the independent read-only reviewer after integration. Keep all work on `feature/mmsp-mx150-final-rtx-ready`.

**Goal:** Finalize a portable MX150 drone-photo-to-dense-cloud runtime and verify the existing CMake path for RTX 3050 (`sm_86`).

**Architecture:** Preserve the merged D1 PowerShell runner and existing COLMAP MVS engine. Add only the external-process contract and local runtime packaging needed to call it outside a development checkout; share the CMake build profile for CUDA architecture selection.

**Tech Stack:** PowerShell 5.1/7, CMake, CUDA 12.x, COLMAP, existing security and artifact guards.

**Spec:** User mandate in the session; repository constraints in `AGENTS.md`, `MODS.md`, `CONTRIBUTING.md`, and `README.md`.

## Global Constraints

- Scope: SfM-to-dense engine, V1 ends at the fused dense point cloud.
- Default work area is `colmap/src/colmap/mvs/` plus its option plumbing; sparse internals, meshing, and GUI need approval first.
- License: permissive-only tree (Apache-2.0, see `LICENSE` + `THIRD_PARTY_NOTICES.md`). No GPL/AGPL/non-commercial code in build or runtime. GPU feature extraction is removed; SfM always CPU SIFT.
- Windows notes: never rebuild while a run uses the binary (file lock); PowerShell goes in `.ps1` files; validate scripts with `tools/parsecheck.ps1`.
- Keep D1 `-ImagesPath` and `-OutputDir`; preserve existing summary fields, read-only inputs, and non-overwriting outputs.
- No merge, force-push, release, or destructive action. Create one PR after all gates.

## Review Focus

- Invalid or missing executable and image inputs must produce a failed versioned summary and nonzero exit code.
- Stage failure must emit a machine-readable event and never leave a success status or exit code.
- Existing/non-empty output folders, reparse points, and inputs must remain protected.
- Runtime must start without a source checkout or developer-only environment file, with required system dependencies documented.
- `sm_61` and `sm_86` must be present in generated CUDA code when the local toolchain supports verification.

## File Structure

- `scripts/run/process-drone.ps1` and `scripts/run/test-process-drone.ps1`: external CLI, versioned JSON, stage events, truthful status/exit code.
- `scripts/setup/configure-mx150.ps1` and `scripts/setup/build-mx150.ps1`: shared CUDA architecture selection while retaining the MX150 default.
- A small runtime preparation script under `scripts/setup/`: copy only runtime files, notices, and runner into a caller-selected folder.
- `README.md` and `MODS.md`: usage, measured gate results, runtime system requirements, and measured optimization decision.
